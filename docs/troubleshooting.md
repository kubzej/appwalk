# Troubleshooting

## `Missing provider` or `Missing model`

Provider and model are mandatory. Pass them directly or define both in a config file that is explicitly supplied with `--config`.

```bash
PROVIDER="your-provider"
MODEL="your-model"
npx tsx src/cli/index.ts run https://your-app.example \
  --provider "$PROVIDER" --model "$MODEL"
```

## Missing provider API key

The selected hosted provider key is not present in the environment. Set the variable matching the selected provider before starting the run. Do not put the raw key in YAML committed to source control.

## `No flows were ready for replay`

The agent may have spent the action budget without completing a flow, returned plain text instead of calling `flowComplete`, or encountered a broken/unreachable page. Read the report and use `--verbose` or `--debug` for the next run. Increasing `--max-steps` can help, but it also increases provider usage.

## A flow was discovered but replay was not confirmed

Discovery is probabilistic and replay is intentionally stricter. Common causes include:

- the target data changed between discovery and replay;
- a locator was ambiguous or depended on transient content;
- a preceding mutation was blocked by the safety guard;
- the agent exhausted its budget in the middle of a journey;
- login state or a required browser storage value was not available.

An unconfirmed flow is not generated by default. Use the exact failure step in `report.html` and `evidence.jsonl` to decide whether the target, authentication, safety policy, or exploration scope needs adjustment.

## Login is not available

Do not pass dummy credentials to a public application. Omit `--email` and `--password` for anonymous exploration. For SSO, MFA, CAPTCHA, or a non-standard login, capture a Playwright storage state and pass `--storage-state`.

## A mutation is blocked

This is the default safety behavior for `POST`, `DELETE`, `PUT`, and `PATCH`. First decide whether the mutation is required for the test. If it is, use a disposable environment and explicitly choose either:

```bash
--allow-destructive
```

or a narrowly scoped safety JSON allow rule. Remember that an allow rule can override the block for its matching URL.

## Rate limiting

Rate limits are provider and organization limits, not per browser session. Multiple persona runs do not receive isolated provider quotas. Coverage runs execute sequentially, but each provider request still includes the context required by that persona.

Use a smaller action budget, avoid screenshots unless the selected model benefits from vision, keep response-variant exploration disabled until the base run is useful, and enable `--debug` to inspect provider request and rate-limit metadata. A repeated request cannot make a token window larger; Appwalk surfaces provider rate-limit failures rather than blindly retrying the same oversized request.

## `--screenshots` does not improve results

Screenshots are sent only where the provider integration supports them, and a text-only local Ollama model cannot use visual input meaningfully. Screenshots also increase request size. Compare a short run with and without the flag before enabling it for a large coverage matrix.

## `generate` says the discovery used login

Generation needs an explicit authentication setup. Appwalk does not reuse auth tokens from discovery artifacts, so pass the original credentials or a storage state:

```bash
npx tsx src/cli/index.ts generate ./appwalk-output/<execution-id> \
  --email "$APP_USERNAME" --password "$APP_PASSWORD"
```

For SSO or MFA:

```bash
npx tsx src/cli/index.ts generate ./appwalk-output/<execution-id> \
  --storage-state ./auth/storage-state.json
```

## Generated tests fail in a different environment

Generated tests preserve the discovered action sequence and may contain response fixtures. They do not provision your application, seed data, or replace the environment configuration of your Playwright project. Review URLs, credentials, storage state, fixture assumptions, and destructive-action behavior before moving them to CI.
